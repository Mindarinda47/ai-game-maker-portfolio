# Codex에 일을 맡기고 확인하는 과정

[포트폴리오](../README.md) · [MYGOATmatch 기술 사례](MYGOATMATCH_CASE.md)

## 1. 문제가 난 상황부터 정리합니다

자동 전투를 돌리다가 두 상황을 발견했습니다. 특정 스킬을 쓰는 상대에게 공격이 연달아 적중해도 효과가 더 쌓이지 않았고, 다른 상태로 전환할 때는 이미 쌓인 효과가 남았습니다. Codex에 각각 어느 상태에서 발생했는지 전달하고, **새 적중을 처리하는 조건**과 **상태 전환 때 기존 효과를 해제하는 조건**을 따로 확인했습니다.

## 2. 수정 범위와 유지할 동작을 같이 적습니다

기존 돌진에 시각 효과를 추가할 때 이렇게 요청했습니다.

> 기존 돌진 이동, 공격 판정, 데미지 등의 로직은 유지하고 VFX 구현과 연동에 집중해주세요.

이미 있는 적중·종료 조건에 연출을 연결하고, 리플레이에 필요한 진행값을 기록하는 작업을 맡겼습니다.

## 3. 판정·상태·연출을 나눠 확인합니다

이동 중 공격이 빗나가는 것처럼 보였을 때는 판정 범위를 화면에 표시해 달라고 했습니다. 화면에 보이는 크기와 접촉 판정을 비교할 수 있게 한 뒤, **어느 타격에서 상대 상태가 바뀌는지**와 **언제 시각 효과가 시작되는지**를 각각 지정했습니다.

## 4. 어디까지 확인했는지 구분합니다

| 확인 | 확인하는 내용 |
| --- | --- |
| 정적 확인 | 변경 파일과 호출부에서 선언·타입·구문을 확인합니다. Godot의 비슷한 이름을 가진 enum을 잘못 연결한 뒤에는 실제 속성 타입을 대조하는 절차를 오류 기록에 남겼습니다. |
| 빌드·자동 테스트 | 빌드가 되는지, 바꾼 동작이 테스트를 통과하는지 확인합니다. Codex가 작성한 누적 효과 테스트는 피해 적용, 남은 시간 감소, 시전 후 누적 재개를 확인합니다. |
| 실제 플레이 | 발동 시점, 피격 결과, 공격 사이에 생기는 지연을 게임에서 봅니다. 표시나 타이밍이 걸린 변경은 리플레이에서 확인할 항목도 함께 적습니다. |

## 5. 플레이에서 본 문제를 수정 조건으로 바꿉니다

두 동작이 너무 빠르게 이어질 때는 앞 동작이 끝난 뒤 짧은 간격을 넣어 달라고 했습니다. 연속 공격이 느리게 느껴졌을 때는 타격 직전 준비 시간과 중복 대기를 확인해 달라고 요청했습니다. Codex가 바꾼 뒤에도 시간·전환 조건·표시 중에서 어느 부분을 더 수정할지는 제가 경기 화면을 보고 결정합니다.
