# Codex에 일을 맡기고 확인하는 과정

[포트폴리오](../README.md) · [MYGOATmatch 기술 사례](MYGOATMATCH_CASE.md)

## 1. 어느 경기에서 어떻게 발생했는지 적습니다

자동 전투에서 연속 공격의 스택이 멈췄을 때, 상대가 프레이를 쓰며 제자리에 있는 동안 라켓이 연달아 맞아도 3스택에서 4스택으로 오르지 않는다고 전달했습니다. 별도로 상대가 궁극기에 진입하면 기존 스택과 보라색 꼬리띠가 남는 장면도 보고했습니다. 적중 순간에 증가를 막는 조건과, 상태가 바뀔 때 기존 스택을 정리하는 조건은 각각 확인해야 했습니다.

## 2. 수정 범위와 유지할 동작을 같이 적습니다

이미 사용하던 돌진에 차크라 손 VFX를 붙일 때 실제로 이렇게 요청했습니다.

> 기존 돌진 이동, 공격 판정, 데미지 등의 로직은 유지하고 VFX 구현과 연동에 집중해주세요.

Codex가 맡은 범위는 준비 동작에서 손이 생기고, 실제 피해가 들어가는 순간 할퀴며, 돌진 종료·벽 충돌·강제 취소에서 손이 수축하도록 연결하는 것이었습니다. 라이브와 리플레이에서 같은 타이밍에 보이도록 할퀴기와 수축의 진행값도 리플레이 프레임에 저장했습니다.

## 3. 화면에서 보이는 문제를 코드에서 확인할 단위로 나눕니다

질주가 잘 맞지 않는 느낌이 들었을 때는 판정 범위부터 화면에 표시해 달라고 했습니다. 그 결과 스프라이트 크기와 판정 크기를 비교할 수 있었고, Codex는 질주 경로와 캡슐을 라이브·리플레이에 표시했습니다. 그 뒤에는 **어느 타격이 다운을 일으키는지**와 **언제 총공격 파편이 움직이는지**를 별도 요구사항으로 전달했습니다. 각각 고칠 코드와 확인할 장면이 달랐습니다.

## 4. 어디까지 확인했는지 구분합니다

| 확인 | 확인하는 내용 |
| --- | --- |
| 정적 확인 | 변경 파일과 호출부에서 선언·타입·구문을 확인합니다. Godot의 비슷한 이름을 가진 enum을 잘못 연결한 뒤에는 실제 속성 타입을 대조하는 절차를 오류 기록에 남겼습니다. |
| 빌드·자동 테스트 | 컴파일 결과와 테스트에 넣은 조건의 통과 여부를 확인합니다. 스택 사례의 회귀 테스트에는 피해 적용, 타이머 진행, 시전 종료 후 증가 재개를 확인하는 조건이 있습니다. |
| 실제 플레이 | 발동 시점, 피격 결과, 공격 사이에 생기는 지연을 게임에서 봅니다. 표시나 타이밍이 걸린 변경은 리플레이에서 확인할 항목도 함께 적습니다. |

스택 사례에서 제가 직접 본 것은 수정 전 경기의 이상 동작입니다. 수정 직후 기록에 남은 확인은 구문과 변경분 점검까지였습니다. 회귀 테스트는 코드에 있고, 그때 실행했다는 기록은 없습니다.

## 5. 플레이 피드백을 다음 조건으로 바꿉니다

변신이 너무 빠를 때는 상대의 준비동작이 끝나는 순간과 변신이 시작되는 순간 사이에 간격을 달라고 했습니다. 연속 공격이 느리게 느껴졌을 때는 타격 직전 준비 시간과 중복 대기를 확인해 달라고 요청했습니다. Codex가 바꾼 뒤에도 시간·전환 조건·표시 중에서 어느 부분을 더 수정할지는 제가 경기 화면을 보고 결정합니다.
