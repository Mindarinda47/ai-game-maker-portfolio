# Codex와 게임을 만드는 방식

[포트폴리오](../README.md) · [MYGOATmatch 개발 사례](MYGOATMATCH_CASE.md)

MYGOATmatch에서 제가 맡는 일은 캐릭터가 어떤 행동을 하고 관전자가 그 행동을 어떻게 읽어야 하는지 정하는 것입니다. Codex에는 현재 코드에서 그 행동이 어디서 결정되는지 찾고, 제가 정한 조건을 기존 시뮬레이션과 화면에 연결하는 일을 맡깁니다.

## 1. 원하는 장면을 전투 규칙으로 적습니다

캐릭터 콘셉트를 정한 뒤 **언제 발동하는지, 누구를 대상으로 하는지, 어떤 조건에서 멈추는지, 어떻게 보이는지**를 적습니다. 예를 들어 구미화 나루토의 할퀴기는 쿨타임이 돌아오면 상대와의 거리와 무관하게 돌진하고, 돌진 도중 사거리 안에 상대가 들어왔을 때만 타격이 들어가도록 정했습니다. 잡기는 돌진을 끊을 수 있도록 예외를 뒀습니다. 이 조건이면 시전 시점과 타격 시점을 각각 확인할 수 있습니다.

## 2. Codex에 바꿀 부분과 지킬 계약을 함께 줍니다

같은 스킬에 차크라 손 연출을 추가할 때는 다음 범위를 전달했습니다.

> 기존 돌진 이동, 공격 판정, 데미지 등의 로직은 유지하고 VFX 구현과 연동에 집중해주세요.

Codex는 기존 준비 시간 안에서 손이 형성되고, 실제 피해 이벤트에서 할퀴며, 돌진 종료·벽 충돌·강제 취소에서 수축하도록 연결했습니다. 할퀴기와 수축의 진행값은 리플레이 프레임에도 저장했습니다. 이렇게 하면 전투 규칙을 바꾸는 요청과 그 규칙을 화면에 표현하는 요청을 개별적으로 확인할 수 있습니다.

## 3. 플레이에서 관찰한 조건으로 다음 수정을 좁힙니다

와루이지 스택이 이상했을 때는 상대를 퀸으로, 상황을 프레이 시전 중으로, 기대한 전환을 3→4스택으로 특정했습니다. 이 관찰에서 출발해 일반 피해·스택 증가·기존 스택의 남은 시간을 각각 정했습니다. 퀸 궁극기 진입의 스택 초기화는 별도 조건으로 다뤘습니다.

연출도 같은 방식으로 피드백을 줍니다. 메타몽 변신이 빠르다고 느꼈을 때는 **우사기 준비동작 종료부터 메타몽 변신 시작까지의 간격**을 지정했습니다. 퀸 총공격에서는 **점프에서 균열 생성, 초상의 반사광에서 파편 움직임 시작**으로 장면을 나눴습니다.

## 4. 확인한 결과를 다음 작업에 남깁니다

초기에는 캐릭터 기술과 미세 조정을 주로 대화에서 설명했습니다. 작업이 이어지면서 프로젝트 지침과 캐릭터별 문서에 공용 전투 상태, 실시간·리플레이 연결 지점, 값을 바꿀 위치를 남겼습니다. 11월에는 반복되는 오류를 유형별로 기록해 다음 작업에서 참고하도록 Codex에 요청했습니다. 예를 들어 C# 구문 확인에서 놓친 Godot API 타입 오류는 실제 속성 타입과 호출부를 대조하는 규칙으로 남겼습니다.

변경 보고에서 **정적 점검**, **빌드·테스트**, **게임에서 관찰한 동작**은 각각 확인 범위가 다릅니다. 와루이지 사례의 직접 플레이 기록은 문제를 발견한 시점의 것이고, 수정 직후 Codex의 보고는 구문 점검까지였습니다. 이 차이를 남겨야 다음에 실행할 경기를 정할 수 있습니다.

### 작업 기록의 변화

- **Website Escape Game**에서는 먼저 탐색에서 엔딩까지 이어지는 버전을 구현하고, 지인 테스트에서 막히는 부분을 발견해 힌트를 보강했습니다. [제작 사례](WEBSITE_ESCAPE_CASE.md)
- **Boombi**에서는 모델이 다룰 비정형 입력과 코드에서 계산할 결과의 경계를 정의했습니다. [시스템 설계 사례](BOOMBI_CASE.md)
- **MYGOATmatch**에서는 기존 전투 상태, 표시, 리플레이가 얽힌 수정에서 발동 조건과 타이밍을 지정하고, 실제 경기에서 발견한 예외를 다음 요구사항에 반영합니다. [자동전투 사례](MYGOATMATCH_CASE.md)
